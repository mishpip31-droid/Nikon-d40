# Карта функций A 1.11 и B 1.11 (v16)

Новый в v16 статический анализатор `tools/frdis/` строит перечень функций,
граф вызовов и обращения к памяти по всему образу. Он только читает BIN;
код прошивки не исполняется. Результаты лежат в `data/function_map/`.

## Итог

| | B 1.11 | A 1.11 |
|---|---:|---:|
| Функций | 4672 | 1539 |
| из них достоверность high / medium / low | 2263 / 2115 / 294 | 353 / 1083 / 102 (+1 invalid) |
| Инструкций | 331 429 | 91 647 |
| Байт кода | ≈811 КБ | ≈211 КБ |
| Функций с недопустимой инструкцией | 0 | 1 (адрес атласа `0xFEB0C` — таблица, не код) |
| Разобрано таблиц `switch` | 77 | 28 |
| Неразрешённых косвенных переходов | 64 | 2 |

Точные числа — `data/function_map/*/summary.json`; сводки — `MAP_A.md`,
`MAP_B.md`.

**Достоверность.** high — функция достижима от векторов прерываний, таблицы
задач или адресов атласа по разрешённым вызовам; medium — есть вызывающие или
не меньше 20 инструкций; low — короткая функция без вызывающих (возможно,
данные).

## Метод

1. Рекурсивный обход от векторов (`0xAFC00` в B, `0x3FC00` в A), статической
   таблицы задач REALOS (только B) и адресов `data/symbols.csv`.
2. Отслеживание констант в регистрах: разрешаются `LDI:32 #X,r12; CALL @r12`,
   хвостовые `JMP @rN`, таблицы `switch` компилятора Softune
   (`CMP #N; …; LD @(r13+r12),r12; JMP @r12`).
3. Указатели на функции: константы, которые записываются в память как значение
   или передаются аргументом вызова; таблицы указателей в данных.
4. Пролог Softune (`ST ri,@-r15` / `STM` / `ST RP,@-r15` / `ENTER`) и места
   вызова в ещё не разобранных участках. Каждый кандидат принимается только
   если вся цепочка его вызовов декодируется без недопустимых конструкций:
   неизвестный код, переход в слоте задержки, `INT` с номером < 0x40,
   `ENTER` не в начале функции, перекрытие уже принятого кода.

Адреса: B — `CPU = файл + 0x40000`, плюс копия служебного кода в RAM
`0x83CE8658` (из файла `0x11CB6C`); A — `CPU = файл + 0xC0000`.

## Что выдаётся

| Файл | Содержимое |
|---|---|
| `functions.csv` | вход, смещение файла, имя из атласа, источник, размер, блоки, вызывающие/вызываемые, вызовы ОС, достоверность |
| `callgraph.json` | вызывающая → вызываемые |
| `xrefs.json` | обращения к памяти/периферии по константным адресам; прямая адресация I/O |
| `os_calls.json` | `INT 0x40` по коду (r12) → функции |
| `strings.csv` | ASCII-строки и ссылающиеся функции |
| `B/tasks.csv` | статическая таблица задач ОС B |

Листинги не входят в атлас: они содержат байты прошивки. Пересоздать:

```bash
python3 tools/frdis/analyze.py B /path/BD400111.bin out/B data/symbols.csv
python3 tools/frdis/analyze.py A /path/AD400111.bin out/A data/symbols.csv
python3 tools/frdis/report.py B out/B /path/BD400111.bin > MAP_B.md
```

Полный прогон B занимает около 15 минут.

## Ядро ОС (B)

* Системный вызов `INT 0x40`, код в r12 (знаковый байт), диспетчер
  `0xC1586`, таблица 16-битных смещений обработчиков относительно `0xC157E`.
* Коды, подтверждённые по обработчикам или вызывающему коду (μITRON 3):
  −23 `sta_tsk`, −21 `ext_tsk`, −20 `ref_tsk` (0x10 = DORMANT), −24 `get_tid`,
  −85 `dly_tsk`, −53 `wai_sem`, −55 `sig_sem`, −48 `set_flg`, −47 `clr_flg`,
  −46 `wai_flg`.
* Таблица задач `0xEA868`: u16 число (24), u16 размер записи (0x1C); запись —
  TCB, u16 номер, u16 приоритет, 0, атрибут, вход, вершина стека, 0.
* `0x44BE8(id)` / `0x44C26(id)` — захват/освобождение ресурса (семафор,
  владелец в `0x83CE9064[id]`), самые вызываемые функции прошивки;
  `0x44B76…0x44BD0` — двусвязные списки.

## Ограничения

* Функции, вызываемые только через неразрешённые косвенные переходы и без
  стандартного пролога, могут отсутствовать.
* Назначение известно только у функций, разобранных в отчётах атласа.
* Разрешение обращений к памяти работает только когда базовый регистр
  загружен константой в том же блоке.
