# Отдельный пункт Cinema2383 в Nikon D40 — исследование v11

**Исторический отчёт v11. Актуальная сборка EXP02 и решение размещения описаны в [MENU_BUILD_RU.md](MENU_BUILD_RU.md).**
28 октября 2026 года. Только точный оригинал D40 B 1.11 с SHA-256 `b9df48d461e875dce4ba84da88164af170dfc48ad9f7674859623bad0401032e`.

**Подготовлены и проверены два прототипа CPU: выбор отдельной восьмой строки и восстановление позиции курсора. Устанавливаемой прошивки с новым меню пока нет.** Размещение изменяемых записей меню в реальной RAM, размещение новой строки текста и полный цикл событий интерфейса ещё не подтверждены. Прототипы специально не записывают полный BIN и не пересчитывают его CRC.

## Предлагаемое управление

В P/S/A/M: `Shooting menu → Optimize image → Cinema2383`.

Планируется сохранить семь существующих строк и добавить восьмую:

| Индекс | Название | Действие |
|---:|---|---|
| 0 | Normal | Штатный режим 0 |
| 1 | Softer | Штатный режим 1 |
| 2 | Vivid | Штатный режим 2 |
| 3 | More vivid | Штатный режим 3 |
| 4 | Portrait | Штатный режим 4 |
| 5 | Black-and-white | Штатный режим 6 |
| 6 | Custom | Переход к существующим пользовательским настройкам |
| 7 | Cinema2383 | Режим Custom = 5, пользовательская тоновая кривая = 6; применить и вернуться |

Новая строка — прямой выбор уже существующего сочетания настроек EXP01. Отдельный новый номер режима в постоянную память не вводится. Резкость, цветовой режим, насыщенность и оттенок наследуются из Custom; это **не независимый банк** с отдельной копией всех параметров. В EXP01 пользовательская цветная кривая уже занята Cinema2383. При выборе Normal тоновая настройка Custom может остаться равной 6, но режим оптимизации переключается штатным способом. Полный путь обработки готового кадра при переключении должен быть дополнительно сопоставлен на камере.

## Почему одной новой надписи недостаточно

Заголовок Optimize image находится в файле `0x119DC0`, при старте копируется в RAM `0x83CE58AC`. Его размер — 32 байта. Поля:

| Смещение | Поле на исследованном пути |
|---:|---|
| +0x00 | Индекс заголовка 0x22 |
| +0x08, +0x0A | Счётчики, оба первоначально 7; полная семантика видимости ещё уточняется |
| +0x0C | Строка внутри видимой области |
| +0x0E | Начало видимой области |
| +0x12 | Индекс экранного обработчика 15 |
| +0x14 | Родитель `0x83CE53CC` |
| +0x18 | Указатель структуры размещения |
| +0x1C | Указатель массива 16-байтных записей `0x83CE58CC` |

Исходный массив занимает `[0x119DE0, 0x119E50)` в файле. Сразу после него расположен **заголовок Custom**, RAM `0x83CE593C`. Восьмая строка по старому адресу попадёт прямо в этот заголовок. Проверка записана как `count_only_eighth_row` в журнале; увеличение счётчиков до 8 без переноса массива не создаёт корректного пункта.

В каждом 16-байтном элементе находятся шесть u16 и один u32: в частности, индекс текста по +2, индекс действия по +0x0A, указатель подменю по +0x0C. Индекс действия выбирает 12-байтную запись из таблицы RAM `0x83CE0798` (файл `0x114CAC`), а адрес обработчика находится по +8 этой записи. Штатные семь строк используют индексы действий 36…42 и общий CPU `0x143FA4`.

**Простое перемещение массива тоже недостаточно.** Штатный обработчик вычисляет адрес выбранной записи и сравнивает его с фиксированными адресами старого массива. В инициализаторе `0x143EF6` адреса строк также зашиты в код.

В тесте после переноса массива в синтетическую RAM `0x20000000` неизменённый инициализатор выбирает сумму индексов **146**, а не допустимую строку 0…7: строка внутри области 145, начало области 1. Это воспроизводимая ошибка неполной правки, а не прогноз физического адреса. `0x20000000` используется только как память интерпретатора и **не предлагается как RAM камеры**.

## Установленная цепочка применения

1. `0x143FA4`: действие строки Optimize image.
2. Выбор обычного пресета изменяет старший полубайт `0x83CE957F` и биты 5:2 `0x83CED225`; Custom сначала открывает подменю, ничего не применяя.
3. `0x144696`: выбор Tone compensation меняет только биты 4:2 `0x83CED224`. Значение Custom — 6.
4. `0x144302`: Done устанавливает режим 5 в этих двух полях режима, вызывает `0x1468AE` с аргументом 2 и возвращает к меню по `0x83CED108`.
5. `0x1468AE`: оборачивает синхронизацию группой событий 9 и вызывает `0x132C3E` с командой 7 и маской `0x00C00000` при установленном бите аргумента 2. В тестах нового обработчика эта функция **заменяется регистрацией вызова**, реальные задачи и ответы не исполняются.
6. На исследованном пути параметров кадра биты тона попадают в `context+0x2C`; `0x31ED1A` извлекает 6, `0x31F7B6` выбирает внутренний селектор кривой 23. Именно этот существующий селектор используется эффектом EXP01.

`0x14C166` выполняет переход в подменю из +0x0C выбранной записи. Это не функция включения эффекта сама по себе.

`0x14325E` проверяет сохранённый номер режима. Исполнен начальный фрагмент до `0x143274` на всех 16 старших и 16 младших полубайтах: номера 0…6 сохраняются, **7…15 сбрасываются в 0**, младший полубайт сохраняется. Новый независимый ID 7 потребовал бы исследования всех потребителей, а не только обхода этой проверки.

## Два прототипа CPU

`tools/menu_shortcut_prototype.py` строит код только в памяти процесса:

- Обработчик выбора — **154 байта** внутри исходного занятого диапазона CPU `[0x143FA4, 0x1441A8)`, размером 516 байт. Он использует индекс выбранной строки, поэтому не зависит от места массива. Семь существующих пунктов проверены дифференциально с оригиналом. Строка 7 выставляет режим 5, тон 6, вызывает штатную синхронизацию и возвращается к родительскому меню. Отрицательные индексы и индексы выше 7 отклоняются.
- Инициализатор позиции — код внутри исходного диапазона `[0x143EF6, 0x143FA4)`. При режиме 5 и тоне 6 выбирает строку 7, при других тонах Custom — строку 6; остальные пресеты сохраняют порядок. Используется исходная функция установки позиции `0x132D0C`.

Обработчик сохраняет регистры r8…r11, r14 и r15 в проверенных вызовах. Изменения полной тестовой RAM для семи штатных строк совпадают с оригиналом. Служебные значения caller-saved регистров и флаги после возврата не объявляются побитно эквивалентными оригиналу.

Инициализатор признаёт любое сочетание Custom/tone=6 режимом Cinema. Отдельный исторический флаг выбора новой строки не хранится. Подпись/значок активного режима в родительском меню также нужно согласовать: существующий участок `0x143B90…0x143BDE` читает значки из старого массива.

Физические таблицы строк/действий, выделение памяти и ветвление реальных кнопочных событий прототипами не заменены. Вызов обработчика напрямую в интерпретаторе **не равен** проверке всего меню.

## Название и языки

В исследованных 15 языковых таблицах по 601 строке и 602 указателя-границы. Отображаемая строка определяется диапазоном `[table[index], table[index+1])`; одного указателя на текст недостаточно. Функции измерения и вывода получают эти границы отдельно:

- CPU `0x7C222…0x7C23E` — передача диапазона функции измерения;
- CPU `0x7CB78…0x7CBB4` — передача диапазона функции отрисовки;
- текущая таблица для этих текстов — указатель `0x83CE3FEC`.

По восьми индексам в каждом языке исполнены оба префикса. Индексы 0…600 в проверенных случаях дают корректные границы. **Индекс 601 без расширения таблицы читает первый текст как следующий указатель и даёт недопустимый диапазон во всех 15 языках.** Поэтому записать `text_index=601` в новый пункт без правки обеих сторон — ошибка.

Название Cinema2383 содержит 10 ASCII-символов. Возможные следующие решения: добавить контролируемый специальный диапазон текста для нового ID в обоих потребителях либо перенести/расширить языковые таблицы с их указателями. Ни один вариант размещения пока не выбран как готовый для устройства. Объединённое имя из двух соседних существующих строк меняло бы и соседнюю подпись, поэтому не подходит для сохранения штатного меню.

## Проверки и ограничения

Команда из корня проекта:

```bash
python tools/check_menu_shortcut.py /path/to/BD400111.bin
```

| Проверка | Число |
|---|---:|
| BANDL/BANDH/BORL/BORH: все 16 масок × 256 байтов, сохранение CCR | 16384 |
| Семь исходных строк: оригинал против прототипа, байтовые поля и варианты прокрутки | 5376 |
| Новая синтетическая строка: режим, тон, вызов и разрешённые записи RAM | 1024 |
| Семь исходных строк после переноса массива в синтетической RAM | 7 |
| Исходный Custom → Tone Custom → Done | 256 |
| Новый обработчик → исходное декодирование → селектор 23 | 18 |
| Переключение Cinema в шесть готовых пресетов | 6 |
| Отклонение недопустимых индексов | 5 |
| Проверка исходного валидатора номера режима | 256 |
| Новый инициализатор: 16 режимов × 256 тоновых байтов × 2 размещения | 8192 |
| Исходные префиксы получения диапазона текста | 240 |
| Отклонение изменённых или пустого исходного образа | 4 |

Проверки на 256 значениях одновременно покрывают каждое значение отдельных байтов по заданным перестановкам; это не полный декартов перебор всех независимых байтов. Восстановление позиции при старом массиве и восьмой строке проверяет только вычисление индекса: реальная старая восьмая запись недопустима и не выбиралась как пункт. Успешное число в журнале не означает завершённое размещение интерфейса.

Машинные результаты: `data/menu_shortcut_validation.json`, `data/menu_label_span_validation.json`. Исходные и предложенные листинги — `evidence/*_v11.asm.txt`. Кандидаты ссылок — `data/menu_shortcut_dependencies.json`; поиск LDI:32 не доказывает отсутствие других способов обращения.

## Что осталось перед проверкой нового меню на камере

1. Разместить 128 байтов восьми **изменяемых** записей в реальной RAM: доказать выделение, время жизни, инициализацию, обработку отказа и отсутствие пересечения с соседними данными. Свободные на вид нули/FF недостаточны.
2. Разместить текст и согласовать оба потребителя диапазона, поддерживаемые языки, отрисовку и ширину подписи.
3. Согласовать указатель массива, счётчики, действие новой строки, видимость/доступность, общий диспетчер, прокрутку и индикацию активного режима.
4. Проверить сохранение, повторный вход, выключение/включение, возврат и ошибки синхронизации. Новые прототипы пока заменяют только два ограниченных обработчика.
5. Собрать отдельную версию поверх точного EXP01, проверить отсутствие пересечения изменений, оригинальные пути, CRC и все новые байты; затем проводить аппаратную проверку отдельного меню.

## Новые сведения с устройства

Пользователь сообщил «Работает», показал экран Optimize image → Custom с пользовательской тоновой коррекцией и передал восемь JPEG. Все восемь файлов декодируются полностью, имеют размер 1536×1021 или 1021×1536 и не содержат EXIF. У отдельных кадров заметен смаз, большинство выглядят тёмными; на последнем есть точечные светлые блики.

Это **первое пользовательское сообщение о работе эффекта на устройстве**, а не испытание нового меню. Хеш установленного на камере образа, установка/завершение записи, разделение Custom/Normal по кадрам и повторные включения не документированы. Поэтому не подтверждены точное соответствие цвета модели, полная стабильность и отсутствие ошибок в светах. Ранее сохранённые документы v1…v10 с числом аппаратных тестов 0 описывают состояние на момент соответствующих исследований.

Оригиналы прошивок и EXP01 в этом исследовании не изменяются. Контроль их байтов записан в `VALIDATION_v11.json`.
