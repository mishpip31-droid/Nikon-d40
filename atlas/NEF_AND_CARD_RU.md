# Путь NEF и запись на карту (B 1.11)

Статический разбор `BD400111.bin`. Код не исполнялся, камера не
использовалась. Номера задач — по исправленной таблице `0xEA868`
(см. FRAME_PIPELINE_RU.md).

## 1. Общая схема (Код)

```
задача 5  считывание в сырой буфер (пул 0x40FE0)
задача 8  проход 0x4001 → YCbCr                     (FRAME_PIPELINE_RU.md)
задача 9  JPEG-обработчик → sta_tsk(10), sta_tsk(11)
задача 10 превью/миниатюра
задача 11 данные NEF: сжатие RAW (блок 0x4009) или копия
задачи 12/13  сборка файлов: 0x77F46(вид 0 = JPEG, вид 1 = NEF)
задача 1  потоковая запись кусков на карту (CF_write)
```

## 2. Данные NEF — задача 11 (`0x48464`)

* Сырой кадр — голова списка `0x83D21208` (`*(head+4)`), адрес данных
  `raw_desc+0x14` (пул 0x40FE0).
* Файловое задание — `*(0x83CE983C)` (его выставляет задача 9).
* Приёмник — `*(file_job+0x0C) + 0x29200`; длина пишется в `file_job+0x18`.
* Режим по байту `0x83CE974B` (= `0x83CE9738+0x13`):

| Условие | Действие | Длина |
|---|---|---|
| бит 5 | копия DMA `0x498BA`: 0x1230 байт × 0x7F2 строк (3104 px × 1,5 × 2034) | `0x908160` = 9 470 304 |
| бит 4 | копия 0x11D0 × 0x7DE (3040 px × 1,5 × 2014) | `0x8C2260` = 9 183 840 |
| иначе | **сжатие блоком 0x4009** (`0x49656`); при ошибке — копия 3040×2014 | из регистров блока |

Смысл этих битов в терминах меню не установлен (в меню D40 нет выбора
несжатого NEF).

## 3. Блок 0x4009 — аппаратный кодер NEF (Код)

Драйвер `0x49656(raw_desc, file_job)`, ресурс 10, IRQ 41 → группа 4, бит
`0x10000000`.

| Регистр | Значение |
|---|---|
| `+0x0C` | вход: `*(raw_desc+0x14)` |
| `+0x10` | выход: `*(file_job+0x0C)+0x29200` |
| `+0x08`, `+0x0A` | 0xBE0 × 0x7DE = 3040 × 2014 (размер RAW D40) |
| `+0x30` | `0x8C2260` — предел выхода (несжатый объём) |
| `+0x14` | u16 из ROM `0xCCC94` = 328 |
| `+0x16…` | 13 кодов Хаффмана из ROM `0xCE8C8` |
| `0x40092000` | 4096 × u16 кривая (`0x4984A`: ROM `0xCC894`; `0x49882`: `0xCA894`) |
| `+0x04`, `+0x06`, `+0x02` | запуск 0x8000, 0xC000, 0x4080 |
| `+0x06 & 7` | статус (0 — успех) |
| `+0x34:+0x36` | сжатый размер → `file_job+0x18` |

**Таблица Хаффмана `0xCE8C8`** — 13 значений u16: код, выровненный влево в 12
битах, и 4 бита длины. Символ → код: 5 `00`; 4 `010`; 3 `011`; 6 `100`;
2 `101`; 7 `110`; 1 `1110`; 0 `11110`; 8 `111110`; 9 `1111110`;
11 `11111110`; 10 `111111110`; 12 `111111111`. Полный префиксный код
(сумма Крафта = 1). По порядку символов и длинам соответствует известному
дереву 12-битного сжатия с потерями Nikon; побайтное сравнение с внешним
источником не выполнялось.

**Кривая `0xCC894`** — монотонная, 4096 входов → 683 уровня (0…682). Длина
683 совпадает с размером кривой, которую NEF с потерями хранит в MakerNote.
**`0xCA894`** — второй вариант, 683 уровня, насыщение 4095 уже к входу 1024;
режим применения не установлен. Текущая загруженная кривая отмечается в
`0x83CE984C` (1 или 2).

## 4. Сборка файла NEF — `0x77F70` (задачи 12/13)

1. Взять буфер у канала записи (`0x77312`) → `file_job+0x0C`.
2. Вызвать подготовку `*(file_job+4)`.
3. Обнулить `0x40080` байт заголовка (`0x4535C`).
4. Построить заголовок TIFF/NEF `0x76E86(buf, 1|2, …)` (MM, IFD, MakerNote
   «Nikon\0\2»); возвращает длину заголовка.
5. Отправить в канал: заголовок; затем данные A — адрес `file_job+0x10`,
   длина из поля `+0x178` связанной структуры (вероятно встроенный JPEG);
   затем данные B — `file_job+0x0C+0x29200`, длина `file_job+0x18`
   (или `0x908160` при бите 5).
6. Куски по `0x80000` байт (или `0x10000` при бите 7 в `job+0x34`); первый
   кусок данных выравнивается так, чтобы записи шли кратно размеру куска.

JPEG собирается `0x7821C` (EXIF — `0x770AE` → `0x76C7A`, таблица тегов
`0xD71FC…`, см. DIAG_OUTPUT_RU.md).

## 5. Очереди файловых заданий (Код)

Пул `0x411B4`: дескрипторы по `0x774` байт с `0x83D022BC`, указатели данных
`0x83D021DC[i]` = `0x82A22300 + i·0x41000`. Списки `0x83D0216C…0x83D0219C`.

| Задача | Вход | Берёт задание | Затем |
|---|---|---|---|
| 12 | 0x77686 | `0x438E8`: список `0x83D0218C` → `0x83D02174` | `0x77712` → `0x77F46` |
| 13 | 0x776D2 (запускается задачей 12) | `0x439FE`: `0x83D02184` → `0x83D0216C` | `0x77D18` → `0x77F46` |

Как файловое задание получает непрерывные ≈9,5 МБ под данные NEF в области
`0x82A22300…0x8385A300`, не прослежено.

## 6. Канал записи и задача 1 (Код)

Двухслотовые каналы на флагах событий: `0x83CEB088` (читает задача 1) и
`0x83CEB058` (читают функции 0x80D4E, 0x84CB6, 0x88638 и др. — вероятно
передача по USB). Слот 0x14 байт: указатель, длина, состояние, статус.
`0x773BA` — положить кусок, `0x77412` — взять, `0x77490` — подтвердить.

**Задача 1** (`0x6D8D0`, приоритет 12) в цикле: взять кусок → `CF_write`
в файл `*(0x83CEB0B8+0x0C)` → прибавить записанное к `+0x14` → подтвердить.

## 7. Файловая система (Код)

* Обёртки `CF_open/close/read/write/create/rename/remove/stat/mkdir/
  GetFreeSpace/…` — `0x6C25E…0x6C754`: ресурс 20 (`wai_sem/sig_sem`), вызов
  ядра, журнал по имени операции.
* Ядро ФС `0xB4000…0xBF000`: дескриптор файла = том<<16 | номер; тома
  `0x83CF0308 + n·0x11A5C`; блокировка тома `0xBCED4/0xBCED8`; коды ошибок
  `0x800050xx`; операции носителя через поля структуры тома
  (`0xBD43C` → `+0x18`, `0xBD474` → `+0x1C` с проверкой номера сектора по
  `+0x44`, `0xBD4BC` → `+0x14`); куча ФС `0xB627A`/`0xB6302`
  (`malloc/free` через указатели `0x83CE8594/0x83CE8590`).
* Пути: `A:\DCIM\100NCD40\`, `DSC_`, `.JPG/.NEF/.NDF`, `A:\MISC\AUTPRINT.MRK`
  (DPOF, пишет `0x79E6C`).
* `0x7982E/0x79870` — счётчик обращений к карте (ресурс 21) и бит 0
  `0x64000028` — вероятно индикатор доступа.

## 8. Не установлено

* Низкоуровневый драйвер SD: команд протокола SD в виде констант нет ни в B,
  ни в A; таблица операций тома заполняется при монтировании и не прослежена.
  Вероятно, обмен ведёт аппаратный контроллер.
* Внешнее устройство `0x65000000` (задачи 21–23, IRQ 47/58/59, DMA `0xC00`) —
  по признакам контроллер USB, не подтверждено.
* Встроенные в NEF изображения (данные A) и полный состав IFD/MakerNote.
* Смысл битов `0x83CE974B` и второй кривой `0xCA894`.
