# Восстановление Nikon D40: состояние на v9

## Документированный сервисный путь

В первичном руководстве Nikon **D40, VBA15001-R.3701.A**, раздел A49 (PDF-страница 77), описано принудительное обновление RISC после замены платы TOGO. Для него указан файл **R330XXXX.BIN** и включение с удержанием кнопок увеличения при просмотре и OK. Это отдельная сервисная процедура. В том же разделе обычное обновление B использует BD40XXXX.BIN.

Проверены обложка D40 и нужная страница полного PDF. В одной строке есть «CF», а следующая говорит об SD; несогласованность исходного документа сохранена как замечание. Материал про L560 и VBA17001 относится к D40X и не использован для выводов о D40.

Источник: [Nikon Repair Manual, раздел A49, зеркало страницы](https://www.manualslib.com/manual/844720/Nikon-Vba15001-Black.html?page=77). [Зеркало полного руководства](https://lens-club.ru/public/files/pdfs/45f735c3f4b5982ab1778810e56331c1.pdf). SHA-256 просмотренного PDF: `fe2091d852486c975057f95aa71a84ef15e78c1d4b4a833691cd9c2d63f3aa39`, 87 страниц. Сам документ не включён в атлас.

**Это подтверждает наличие описанного сервисного пути, но не восстановление после любой порчи B.** Проверенного R330-файла, его формата и испытания на аппарате у нас нет. Эквивалентность R330 и переименованного BD40/EXP01 не установлена.

## Что видно в B 1.11

Обычный путь обновления B не записывает CPU `0x0F0000…0x120000` (конец не включён). Соответствующие file `0x0B0000…0x0E0000` — **196608 байтов FF** в официальном файле.

Это не дамп содержимого этой области на камере. По FF в обновлении нельзя заключить, что физическая flash пуста, доступна для модификаций или не содержит загрузочный код.

Есть два дополнительных свидетельства:

1. Функция `0xAB6C8` читает указатель по CPU `0xFFBC0`. Если он не FFFFFFFF, часть строки версии берётся по этому указателю; иначе формируется значение по умолчанию. В файле обновления этот указатель равен FFFFFFFF. Назначение как дополнительной метаинформации подтверждено кодом; точное содержимое на реальном устройстве неизвестно.
2. Обёртка `0x6B43E` ведёт в RAM `0x83CE88E0`, где отдельная процедура стирает и записывает CPU `0xF0000…0x120000` из RAM `0x81000000`, с тремя попытками. В рассмотренном обычном пути B вызывается другая функция. Вход в дополнительную процедуру пока не восстановлен; её нельзя объявлять доказанным сервисным загрузчиком.

Вектор старта основной B по CPU `0xEFFFC` указывает на `0xC0F90`. Он и код B действительно входят в обновляемые области. **Это не доказывает, что стирается вся возможная загрузочная цепочка устройства.** Для отдельной цепочки данных пока недостаточно.

## Текущее заключение

- Принудительное обновление RISC предусмотрено сервисным руководством D40.
- Обычный B-пакет оставляет отдельную область нетронутой и не раскрывает её содержимое.
- Связь этой области с принудительным режимом пока является гипотезой.
- Надёжный откат после обрыва питания, аппаратное восстановление и установка EXP01 не проверены.

Публичная [инструкция Nikon для штатного обновления](https://cdn-10.nikon-cdn.com/software/firmware/D40/111/D40fw111WIN.pdf) направляет неработоспособную после сбоя камеру в сервис. Она не описывает универсальный пользовательский способ восстановления.

## Что искать дальше

1. Подлинный сервисный R330-образ и его отличия от BD400111.bin: размер, адреса, метаданные и проверка целостности.
2. Код начального загрузчика либо достоверное содержимое незаписываемой области — с происхождением и точной моделью аппарата.
3. Условия включения принудительного режима, его проверки файла и диапазоны записи.
4. Какой минимум загрузочной цепочки должен сохраниться после повреждения B.
5. Только после этого — воспроизводимый план испытания восстановления на отдельном аппарате.

Наличие имени файла и сочетания кнопок не заменяет эти проверки. Ни один сервисный файл или «пакет восстановления» на основании одного переименования в этом исследовании не создавался.


## Уточнение v9

Поиск по имени R330 и доступным первичным материалам не дал проверенного сервисного BIN или полного дампа загрузчика. Это результат проведённого поиска, а не доказательство отсутствия таких файлов. Сервисное руководство повторно сверено: оно описывает процедуру, но не двоичный формат. Официальное обновление A 1.12 перечисляет AD400112.bin, а не R330.

Вместо предположений о содержимом R330 разобран доступный старт A: [A_STARTUP_RU.md](A_STARTUP_RU.md). Обе части используют разные адресные пространства; стартовый адрес A 0xC0042 нельзя переносить на карту B. Успешное исполнение инициализации A в модели не подтверждает независимость сервисного загрузчика от повреждённой B.
