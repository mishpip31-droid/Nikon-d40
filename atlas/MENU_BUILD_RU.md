# Cinema2383 EXP02: отдельный пункт меню

28 октября 2026 года. Собран экспериментальный BIN **D40 B 1.11 + EXP01 + новое меню**. На физической камере EXP02 ещё не проверялась. Пользовательское сообщение о работе предыдущей EXP01 не является проверкой этой версии.

## Результат

В `Optimize image` добавлена восьмая строка **Cinema2383**. Семь исходных строк сохранены. Выбор новой строки устанавливает штатный режим Custom=5 и пользовательский тон=6, вызывает существующую синхронизацию и возвращает в меню съёмки. Повторный вход выделяет Cinema2383, если выбраны Custom и тон=6.

Название помещается в существующую строку: исходная функция измерения шрифта возвращает для него размер 108×20 в единицах обёртки `0x7BBDA` для всех 15 значений языкового переключателя. Это результат исполнения исходного кода, а не измерение ЖК-экрана. Для сравнения использован запас ширины 222; полный вывод пикселей LCD заменён моделью и остаётся аппаратной проверкой.

Название в списке остаётся латинским при любом языке меню. В родительском меню и метаданных используется существующее обозначение Custom: отдельный сохраняемый ID и независимый банк параметров не добавлялись. Резкость, насыщенность, цветовой режим и оттенок берутся из Custom. Для повторения первоначального эффекта: Ia(sRGB), насыщенность Normal, оттенок 0.

Цветовые изменения EXP01 сохранены. Новые изменения находятся в других диапазонах; проверены точная повторная сборка и весь побайтовый результат. Эффект не получил новую настройку силы или другой цветовой вариант.

## Размещение без новой RAM

В v11 рассматривалось выделение RAM для восьми изменяемых записей. Исследование конкретного Optimize image показало другой вариант: исследованные потребители читают записи, а состояние выбора меняют в заголовке меню и таблице действий. Поэтому **только этот список** перенесён в ROM. Остальные меню, включая Custom с изменяемыми значками, сохраняют прежнее размещение.

Под новые данные освобождена часть исходных двух обработчиков после их компактной эквивалентной замены. Не использовались случайные FF-области, предполагаемые свободные адреса RAM или увеличение файла.

| Объект | CPU | Размер |
|---|---:|---:|
| Инициализатор выбора | 0x143EF6 | 74 |
| Перехват измерения нового текста | 0x143F40 | 50 |
| Обработчик выбора | 0x143FA4 | 154 |
| Перехват аргументов отрисовки | 0x14403E | 80 |
| Восемь записей списка в ROM | 0x144090 | 128 |
| Cinema2383, без завершающего NUL | 0x144110 | 10 |

Все эти объекты лежат внутри исходного занятого диапазона CPU `[0x143EF6, 0x1441A8)`. Инициализированный указатель массива в файле `0x119DDC` теперь содержит ROM-адрес. Счётчики по `0x119DC8/0x119DCA` изменены на 8. Заголовок и поля прокрутки продолжают работать в исходной RAM.

Задействованы существующие семь позиций на экране: допустимые начала области 0 и 1. Штатные функции перемещения сами прокручивают список и замыкают его по восьми пунктам. Искусственное начало области 2 недопустимо и не формируется в проверенных последовательностях.

Новая запись использует существующий индекс действия **36**, общий с Normal. Адрес вызываемого обработчика одинаков, но действие различается по выбранному индексу строки. Поэтому доступность и справочные данные новой строки связаны с Normal; отдельная справка Cinema не добавлена. Это ограничение требуется учитывать при будущей доработке условий доступности.

## Вывод подписи

Использован новый индекс текста 601. Два найденных потребителя строк типа 0 перехватывают только этот индекс, передавая диапазон десяти байтов Cinema2383. Для 0…600 выполняется исходная последовательность получения границ. Исходные языковые таблицы не расширяются и не меняются.

Перехваты находятся в файле по `0x3C222` и `0x3CB78`. Проверены все 601 исходное имя и новое имя в 15 таблицах, для измерения и отрисовки отдельно: **18060 случаев**. Исходный код расчёта размеров шрифта также исполнен целиком для новой строки. Пиксельный вывод глифов и значков в этих интеграционных проверках заменён моделями; скриншот меню не синтезировался и не объявляется результатом камеры.

## Что проверено

| Проверка | Результат |
|---|---:|
| Диапазоны всех имён в 15 языках, два потребителя | 18060 |
| Полный штатный расчёт размера Cinema2383 | 15 |
| Штатный составитель списка, обе допустимые области | 2 |
| Штатный диспетчер события выбора, все строки | 8 |
| Перемещения в обоих направлениях, включая замыкание | 256 шагов |
| Возврат к родителю без применения | 8 |
| Исходное копирование перед сохранением и после загрузки | 256 |
| Новые инструкции ограниченного интерпретатора | 1664 |
| Регрессионные проверки исходного атласа | 10 |

Исходные v11-проверки семи пунктов, обработки тона, курсора и недопустимых значений также повторены. В интеграционных проходах любая попытка записи в ROM завершает тест ошибкой. Таких записей не произошло. Это подтверждение перечисленных путей, **не доказательство отсутствия любого возможного позднего обращения к списку**.

Модели явно заменяют: отрисовку LCD/значков, деление в двух библиотечных помощниках, запрос палитры и визуального состояния, установку события/задержку ОС и синхронизацию `0x1468AE`. Диспетчер `0x132286`, перемещения, расчёт позиции и составитель списка выполняются из прошивки. Полное планирование задач, ошибки удалённого обмена и временные зависимости не проверялись.

Для сохранения исполняется оригинальный путь `0x403FA` до входа в функцию журнала. Затем тест моделирует возвращение тех же байтов блока и исполняет оригинальную копию `0x40520…0x40530`. Сохраняются режим 5 и тон 6, после чего новый инициализатор выбирает строку 7. **Запись flash и настоящее выключение/включение в этой проверке не выполнялись.**

## Проверка файла

Готовый файл и манифест находятся в `experimental_firmware_EXP02/`.

- Размер: **3 997 696 байт**.
- SHA-256: `56de8eda261cd13655a09a981ede0f2e56dd5236b308714c5fafe3ebc413d22b`.
- Конечный CRC16/XMODEM: `3E70`; остаток всего файла 0.
- Строка версии B 1.11 сохранена; A не изменяется.

Исполнен исходный предварительный разбор размера/идентификатора с файлами в памяти. CRC сверена двумя способами: моделью исходной ROM-таблицы и `binascii`. Все изменённые байты попадают в найденные программируемые диапазоны обновления B. Условия на конкретной камере, фактическая запись, запуск и восстановление этим не доказываются.

Поиск внешних литералов обнаруживает старую таблицу переходов и сохранённые входы функций; единственная найденная буквальная ссылка на старую таблицу находится в заменённом коде. Дополнительные совпадения разобраны как поля пункта Small picture и байты шрифтов. Два похожих относительных CALL оказались половинами LDI:32. Это ограниченная проверка ссылок, а не полный анализ всех вычисляемых переходов.

## Воспроизведение

```bash
python tools/check_menu_integration.py /path/to/BD400111.bin /path/to/EXP01.bin
python tools/build_menu_experiment.py /path/to/BD400111.bin /path/to/EXP01.bin --output /path/to/new_EXP02_directory
python tools/check_menu_binary.py /path/to/BD400111.bin /path/to/EXP01.bin /path/to/EXP02.bin
```

Принимаются только точный исходный B 1.11 и точный EXP01 с закреплёнными хешами. Каталог сборки должен быть новым. Имена файлов в примере условные: проверяются байты.

Артефакты проверки: `data/menu_integration_validation.json`, `data/EXP02_binary_validation.json`, `VALIDATION_v12.json`. Прототипы v11 сохранены как история; актуальная сборка — `tools/build_menu_experiment.py`.

Для новых инструкций использовано первичное руководство Fujitsu CM71-00101-5E, разделы 7.32, 7.36, 7.37 и 7.44: [документ производителя в зеркале](https://dtsheet.com/doc/1555293/5.5mb), [LSL](https://www.manualsdir.com/manuals/103548/fujitsu-fr-family-32-bit-microcontroller-instruction-manuel-cm71-00101-5e.html?page=162). Точные пределы ранее унаследованного интерпретатора сохраняются; это не полная эмуляция процессора.
