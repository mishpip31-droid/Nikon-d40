# Канал вывода диагностики из камеры (B 1.11 / EXP04)

Задача: получить с камеры несколько чисел на каждый снимок (контрольные суммы
участков плоскостей YCbCr, адреса, счётчик кадров) без изменения изображения
и без риска для обновления прошивки. Статический разбор; на камере не
проверялось.

## Сравнение вариантов

| Канал | Объём | Риск | Вывод |
|---|---|---|---|
| **EXIF UserComment** (тег 0x9286) | **36 символов ASCII на снимок** | малый: две правки в писателе тега, буфер вне настроек | **выбран** |
| EXIF Software (0x0131) | 9 символов | указатель `0xEFBF0` на строку версии читают ещё 10 функций, в т. ч. обновление и PTP | нет |
| EXIF ImageDescription (0x010E) | 32 символа | писатель `0x73538` заполняет пробелами; нужен новый код | запасной |
| Строки режима в MakerNote (`0xD5BE8…`, 16 байт) | 15 символов | выбор по индексу режима, таблица в ROM | нет |
| Пиксели изображения/миниатюры | много | JPEG с потерями искажает биты, портит снимок | нет |
| Свой файл на карте | много | файловая система не разобрана | позже |
| PTP по USB (свойство комментария) | 36 символов | требует писать в сохраняемую настройку `0x83CED112` | нет |
| Экран | — | интерфейс отрисовки не разобран | нет |

## Как пишется UserComment (Код)

Таблица дескрипторов тегов EXIF — ROM `0xD71FC…` / `0xD743C…`, запись 16 байт:
`u16 тег, u16 тип, u32 длина, u32 значение по умолчанию, u32 функция-писатель`.
Для UserComment: тип 7, длина 44, писатель **`0x741F6`**. Сборка EXIF идёт в
задачах 12/13 (`0x77686`, `0x776D2`; `0x7821C` → `0x770AE` → `0x76C7A`), т. е.
после обработки кадра (задача 8) и JPEG (задача 9).

`0x741F6` пишет `"ASCII\0\0\0"` (ROM `0xD68A4`), затем 36 байт:

```
job = *(arg+0x144)
если job+0x3C ∈ {0, 7}:                      // обычная съёмка
    если бит 7 байта job+0x744:  копировать 36 байт из 0x83CED112
    иначе:                        36 пробелов
иначе:                                        // ретушь/копия
    копировать 36 байт из 0x83D288A0
```

* `0x83CED112` — сохраняемая настройка «комментарий к снимку» (её также
  обслуживают PTP-функции `0x399E42`/`0x399F56`). **Не трогаем.**
* `0x83D288A0` — комментарий исходного файла: `0x572BC` при просмотре/ретуши
  читает тег 0x9286 существующего JPEG и записывает сюда 36 байт (текст или
  пробелы). При обычной съёмке буфер не используется.

## Выбранная схема

1. **Буфер текста:** `0x83D288A0`, 36 байт ASCII.
2. **Правка писателя** (байты одинаковы в B 1.11 и EXP04):

   | CPU | Файл | Было | Станет | Смысл |
   |---|---|---|---|---|
   | 0x74242 | 0x34242 | `f2 0a` (`BEQ:D 0x74258`) | `9f a0` (`NOP`) | всегда копировать; слот задержки `ADD #8,r8` выполняется как обычная инструкция |
   | 0x74246 | 0x34246 | `9f 80 83 ce d1 12` (`LDI:32 #0x83CED112,r0`) | `9f 80 83 d2 88 a0` | источник — диагностический буфер |

   Изображение, настройки и путь ретуши не меняются. Без работающего
   перехвата UserComment покажет прежнее содержимое буфера (пробелы или
   комментарий последнего просмотренного файла) — это тоже информативно.
3. **Перехват** сразу после `0x4B260` в обёртках (`0x4AE3E`, `0x4AE8E`,
   `0x4AF02` — вызовы `CALL:D 0x4B260`): вызвать диагностическую функцию с
   `out_desc` (r9/r5 у вызова), затем продолжить исходный путь. Функция
   формирует строку, например:

   ```
   NNNN BBBBBBBB YYYYYYYY CCCCCCCC F
   │    │        │        │        └ флаги (вариант −16, k пула)
   │    │        │        └ сумма участка Cb+Cr
   │    │        └ сумма участка Y (64 строки × 64 байта в центре)
   │    └ база выходного буфера *(out_desc+0x0C)
   └ счётчик кадров
   ```

   36 символов = 4+1+8+1+8+1+8+1+1+3 запас. Чтение только, плоскости не
   изменяются.

## Ограничения

* **Соответствие кадру.** Текст для кадра k пишется в задаче 8, EXIF кадра k
  собирается позже в задачах 12/13. При серийной съёмке с двумя выходными
  буферами перехват кадра k+1 может успеть перезаписать буфер. Для первой
  проверки — одиночные кадры с паузой до окончания записи; счётчик кадров в
  строке позволяет заметить несоответствие.
* **Ретушь после диагностики.** Если `0x572BC` не найдёт тег у исходного
  файла и выйдет раньше записи, ретушированная копия может получить
  диагностический текст. На изображение это не влияет.
* **Код перехвата** нужно разместить в программируемой и свободной области
  ROM (как арена EXP04 по CPU `0x33692E`) и проверить тем же способом, что
  EXP04: исполнение исходного вызывающего кода + перехвата + возврат
  в исходный путь в интерпретаторе; сохранность регистров и стека.
* Как и раньше, физическая установка и восстановление не подтверждены.

## Как прочитать на компьютере

`exiftool -UserComment файл.JPG` или любой просмотрщик EXIF (поле «User
Comment»).
