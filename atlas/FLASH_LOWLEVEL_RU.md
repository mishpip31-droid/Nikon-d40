# Низкоуровневое обновление D40 — v8

28 октября 2026 года. Оригинал: B 1.11, SHA-256 `b9df48d461e875dce4ba84da88164af170dfc48ad9f7674859623bad0401032e`.

## Результат и границы

Исполнены оригинальные функции определения ветви flash, выдачи команд записи и стирания, опроса статуса, проверки записанных данных и пустой области. Дополнительно исполнены условия допуска, обмен запросом/подтверждением и завершающий участок обновления. **Все проверки проходят на компьютере.**

Ответы flash, значения аппаратных регистров и события ОС заданы моделью. Это не эмуляция электрических свойств микросхемы, питания, таймингов шины или всей камеры. Физическая запись и восстановление не проверены. EXP01 не менялся.

Подробный журнал: [data/flash_lowlevel_validation.json](data/flash_lowlevel_validation.json). Исходный код проверок: [tools/check_flash_lowlevel.py](tools/check_flash_lowlevel.py). Прежняя проверка файла и порядка диапазонов сохранена в [UPDATER_RU.md](UPDATER_RU.md).

## 1. Две ветви работы с flash

RAM-функция `0x83CE8658` посылает последовательность `AA,55,90`, читает 32 бита по CPU `0x40000`, сохраняет их в RAM `0x83CEA3CC`. Старшие 16 бит сравниваются с `0x00BF`; результат записывается байтом в `0x83CEA3E8`. Затем выдаётся `F0` по адресу `0x400AAA`.

| Признак | Ветвь 0 | Ветвь 1, идентификатор 00BF |
|---|---|---|
| Адреса команд разблокировки, CPU | 0x400AAA / 0x400554 | 0x4AAAA / 0x45554 |
| Запись полуслова | AA,55,A0,данные | AA,55,A0,данные |
| Стирание | AA,55,80,AA,55,30 | Та же последовательность для каждой группы 0x1000 байтов |
| Опрос | Бит 7; при несовпадении проверяется бит 5 и делается повторное чтение | Ожидание совпадения бита 7, без ветви по биту 5 |
| Выход из ошибочной операции через 0x83CE8CB0 | Запись F0 по 0x400AAA | Функция не выдаёт команду |

Это различие кода, а не измерение установленной микросхемы конкретного аппарата. Идентификатор 00BF согласуется с документацией SST/Microchip, но точная модель и ревизия flash здесь не установлены. Не следует подменять одну ветвь другой.

Проверены восемь сочетаний прочитанного идентификатора и состояния блокировки. При нуле RAM `0x83CEA3D0` код вызывает системные операции `-8/-7`, обозначенные в ранее сохранённой таблице REALOS как блокировка/разблокировка CPU; сами системные эффекты моделируются.

## 2. Проверка стирания и геометрия

Внешняя функция `0x83CE8954` выравнивает адрес вниз и выбирает шаг:

- обычно 0x10000 байтов;
- при `(address & 0x3F0000) == 0x3F0000` — адреса и длины из RAM-таблиц `0x83CE0154/174`: восемь групп по 0x2000.

После каждой команды `0x83CE8B02` вызывается **проверка всей группы на полуслова FFFF** через `0x83CE8A9E`. Ошибка команды либо непустое полуслово дают результат 0 и прекращают текущий вызов.

Это группировка, которую использует программа. В ветви 00BF одна такая группа дополнительно стирается командами по 0x1000 байтов. Проверены обычное выравнивание, переход к малым группам, верхняя граница и прекращение при ошибке. Геометрические проверки используют заглушки внутренних операций; сами внутренние функции проверены отдельно.

## 3. Запись и полное сравнение

`0x83CE89E0` вычисляет число полуслов как `(length + 1) >> 1`. Для каждого полуслова вызывается `0x83CE8BE8`. Значение FFFF пропускается, что предполагает предварительно стёртую область.

После завершения записи **весь переданный диапазон сравнивается с исходным буфером** функцией `0x83CE8A2E`, полуслово за полусловом. Это проверка данных, а не только успешного ответа микросхемы. Несовпадение возвращает ошибку; в ветви 0 вызывается выход из режима flash через F0.

Пять проверок намеренно меняют младший бит записанного полуслова, оставляя бит 7 правильным. Опрос признаёт запись завершённой, но окончательное сравнение обнаруживает порчу. Проверены 26 сочетаний ветви и длины, включая нулевую и нечётную длину. При нечётной длине затрагивается полное последнее полуслово; штатные диапазоны обновления имеют чётную длину.

Модель мгновенно записывает значение в обычную память компьютера. Она не имитирует ограничения программирования 1→0, износ, выдержки времени и реальные ошибки питания.

## 4. Ожидание окончания операции

Функция `0x83CE8C7A`:

1. Читает полуслово по адресу операции.
2. Если его бит 7 совпадает с битом 7 ожидаемых данных — возвращает 1.
3. В ветви 00BF при несовпадении сразу повторяет чтение.
4. В ветви 0 при нулевом бите 5 повторяет чтение; при единичном — читает ещё раз и возвращает 0, если бит 7 по-прежнему не совпадает.

**В этом цикле нет счётчика попыток, чтения времени или обслуживания сторожевого таймера.** При постоянном «не готово» моделируемое исполнение не выходит из цикла и останавливается только внешним лимитом проверочного инструмента. Внешний аппаратный сброс/сторожевой таймер не исследован, поэтому это не утверждение о неизбежном вечном зависании всей камеры.

Проверены 1024 сочетания ветви, ожидаемого бита 7 и первого байта статуса с готовым следующим ответом; два подтверждённых отказа и четыре постоянно занятых состояния. Три попытки внешнего управляющего кода не помогают, пока внутренняя функция не вернула результат.

## 5. Условия допуска к обновлению

Оригинальный `0xAB646`, включая `0x40DDA`, исполнен на всех 128 сочетаниях семи логических входов.

| Условие для допуска | Адрес/операция |
|---|---|
| Три 16-битных поля должны быть нулевыми | RAM 0x83CE905E, 0x83CE905A, 0x83CE9054 |
| Бит 5 должен быть снят | MMIO 0x50000107 |
| Бит 6 должен быть снят | RAM 0x83CE971E |
| Байт должен быть ненулевым | RAM 0x83CEB168 |
| Системный опрос должен вернуть код 0 | INT 0x40, код -106, группа 6, маска 0x20000000, режим 2 |

Физический смысл всех входов не установлен. Поэтому эти условия нельзя называть полной расшифровкой проверки батареи и готовности устройства. Дополнительно найден источник RAM `0x83CEB168`: результат функции `0x6C068(0)` приводится к байту в участке `0x78630`; назначение источника ещё нужно проследить.

## 6. Запрос, подтверждение и срок ожидания

`0xAB9F8` обнуляет три байта начиная с RAM `0x83CE9508`, выставляет бит 7 в `0x83CE950B` и ставит команду 13. Успех означает установленный бит 7 в `0x83CE9508`.

Ожидание использует группу событий 3 и маску 0x4000. Общий бюджет — **500 единиц счётчика**, который оригинальный `0xC13F2` читает из MMIO `0x68000114`. Соответствие единиц миллисекундам не установлено.

После возврата из ожидания сначала пересчитывается прошедшее время. При достижении 500 функция возвращает 0 до следующей проверки подтверждения. Исполнены девять сценариев, включая немедленный ответ, несколько ожиданий, отсутствие ответа, границы 498/500 и переполнение 32-битного счётчика.

Связанный обработчик `0xAA1EC` устанавливает событие. При одновременно выставленных запросе и подтверждении он снимает бит 4 MMIO `0x50000106` и вызывает системную операцию выхода задачи. Проверены четыре сочетания этих флагов. Перенос данных от другой стороны обмена всё ещё не эмулируется.

## 7. Конец обновления — не прямой переход к новому B

Участок `0x83CE8892` выбирает разные выходные указатели для успеха и отказа. При успехе вызывает задержку и `0x83CE8EC0`; при отказе пропускает эту подпрограмму. Выполнены четыре сочетания исхода и флага отображения.

`0x83CE8EC0` выдаёт последовательность MMIO-записей, в том числе передаёт значение FC04 по 16 тактам через `0x5000010B/10D`, меняет другие регистры и возвращается. Значение этих сигналов для конкретных периферийных узлов ещё не доказано.

Обе ветви затем устанавливают бит 4 MMIO `0x50000106` и доходят до самоперехода `0x83CE88DE`. **Прямого перехода к старту B в этом фрагменте нет.** Физическое выключение, реакция аппаратуры и следующий холодный запуск не моделировались. Официальная инструкция Nikon предусматривает выключение аппарата после завершения обновления.

## 8. Воспроизведение и ограничения интерпретатора

```sh
python tools/check_flash_lowlevel.py /path/BD400111.bin --output /path/flash_lowlevel_validation.json
```

`fr_update_machine.py` — отдельное развитие интерпретатора v7; прежний `fr_color_machine.py` не изменялся. Добавлены ADDSP, побайтовые BAND/BOR и явная модель INT 0x40. Исходные инструкции прошивки не заменялись. При нормальном возврате каждой проверяемой функции дополнительно проверяется баланс стека. Неизвестные инструкции и обращения к неописанной памяти завершают тест ошибкой.

Модель не реализует всю ISA, исключения, параллельные задачи, реальные прерывания, особенности шины или полный набор эффектов сдвигов на флаги; в исследуемых ветвях зависимость от неучтённых флагов не обнаружена. Тесты с внешними лимитами явно отделены от обычного успешного возврата.

## Следующий шаг

Разобрать формат сервисного R330-файла и код принудительного обновления; установить фактическое содержимое незаписываемой области и условия её запуска. Отдельно выяснить происхождение флагов допуска и смысл аппаратных сигналов завершения. Найденные ограничения не исправлялись патчем: изменение самого обновляющего кода сейчас не требуется для цветового эффекта.
